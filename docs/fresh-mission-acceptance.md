## Repeat the acceptance procedure

This procedure repeats the workflow, not the exact model output. Different runs can fail or produce different plans.
Use your own authorized Bedrock account. Calls can incur provider charges and send task content to AWS.
Do not use an existing owner database. Keep external writes disabled throughout.

### 1. Install the tested revision

In a new disposable directory:

```sh
git clone --branch v0.2.0 --depth 1 https://github.com/iamaanahmad/agentforge.git agentforge-mission-test
cd agentforge-mission-test
git rev-parse HEAD
# Expected: 0e1e85c2a014da7eabdab2c1c68cea4b91425d00
uv sync --frozen --group dev
uv run python scripts/bootstrap.py
```

Python and uv must already be installed. The original mission used Python 3.13.5 and an existing package cache.
Keep the new `.env` private. Read its generated owner password locally without capturing it in evidence.
Save this report's public evidence directory separately; the release tag predates this documentation.
Use its `draft.json` as the input record, never as a database to restore.

### 2. Configure the isolated model route

Create an owner-only directory outside the clone and its data directory.
Replace `/private/mission-test` below with that directory's absolute path.

```sh
uv run python -m agent4good.vault init-key /private/mission-test/keyring.json
```

Edit the new `.env`, preserving the generated password and session secret.
Replace its existing origin line and add these settings. Avoid duplicate keys.

```dotenv
A4G_PUBLIC_ORIGIN=http://localhost:8010
A4G_DATA_DIR=./data
A4G_CREDENTIAL_KEY_FILE=/private/mission-test/keyring.json
A4G_MODEL_PROFILES={"cloud":{"provider":"bedrock","model":"us.anthropic.claude-sonnet-4-5-20250929-v1:0","region":"us-east-1","max_output_tokens":4096}}
A4G_MODEL_ROUTES={"planning":"cloud","coding":"cloud","browsing":"cloud","research":"cloud","summarization":"cloud","verification":"cloud"}
```

Prepare private credential JSON using the [Bedrock setup guide](cloud-models-and-skills.md#aws-bedrock).
Grant only strategist:

```sh
uv run python -m agent4good.vault put bedrock_credentials --agent strategist --stdin < /private/mission-test/bedrock.json
```

Remove that temporary credential file after import. See [vault boundaries](credential-security.md#set-up-the-encrypted-vault).
Confirm port 8010 is unused. Start the web service and worker in separate terminals from this clone:

```sh
uv run uvicorn agent4good.app:create_app --factory --host 127.0.0.1 --port 8010
```

```sh
uv run python -m agent4good.worker
```

Sign in at `http://localhost:8010`. Confirm Connections shows encrypted-vault storage and configured Bedrock routes.
Do not copy credentials, key files, sessions, or data from another installation.

### 3. Draft and start through the browser

Open Missions. Copy objective, criteria, constraints, tools, agents, and budgets from the public `draft.json` spec.
Keep the TEST title and `writes=false`. Set a new deadline one hour ahead; the recorded deadline has expired.
Use two owner-review criteria, strategist, artifact_write, and the recorded three-task budget.
Saving must leave a draft without child tasks. Start through the mission button without supplying a plan.
Inspect the live planner, its revision, the deliverable task, and its successful artifact receipt.
Download the result. The mission must remain `needs_evidence` until its owner criteria pass.
The [mission API contract](missions.md) describes these controls and fields.

### 4. Review before accepting

Read the entire downloaded artifact yourself. Do not accept the model's summary as proof.
Check all three options, recommendation, three interview questions, unknowns, and AWS disclosure.
Count words independently and reject unsupported claims through the owner review form.

If correction is needed, preserve the first artifact. Add one dependent step through the authenticated plan API.
Use `correction-plan.json` as the recorded example, adjusting the prompt to your actual failed claims.
Replace `expected_revision` with your current revision and `depends_on` with your actual original step key.
Do not submit the recorded correction blindly when the new output has different problems.

API requests require an owner session, matching Origin, and the login response's `X-CSRF-Token`.
These are the endpoint and body shapes; substitute your own mission ID and current plan values:

```text
POST /api/missions/{mission_id}/plan
Content-Type: application/json
<body with expected_revision, reason, and steps, as in correction-plan.json>

POST /api/missions/{mission_id}/control/verify
Content-Type: application/json
{}
```

This is an owner intervention, not autonomous replanning. Never silently raise the original budget to force a pass.
Review the new artifact. Record evidence naming its exact artifact ID for each accepted criterion.
Click Check completion. Require both criteria met, all required tasks done, and mission status `done`.
If the budget expires or criteria fail, retain that failure instead of claiming success.

### 5. Verify retrieval and retire the test

Sign out. An unauthenticated `GET /api/missions` must return 401.
Sign in with a fresh session and download both artifacts through their `/api/artifacts/{id}` links.
Require HTTP 200, retained completed status, and unchanged bytes.
Stop and restart only the test web and worker. Repeat login, mission inspection, and both downloads.
Compare each download's SHA-256 before and after restart:

```sh

```

Compare corresponding files within your run. A new run should not be expected to match this report's artifact hashes.
Save sanitized contracts, plans, reviews, receipts, usage, and retrieval checks before cleanup.
Revoke the imported test credential:

```sh
uv run python -m agent4good.vault revoke bedrock_credentials
```

Stop both test processes. Remove only your disposable clone, test data, and external test key.
Confirm port 8010 is closed and any original installation still answers its `/healthz` endpoint.
Never publish `.env`, private keys, credentials, database copies, or unreviewed transcripts.
